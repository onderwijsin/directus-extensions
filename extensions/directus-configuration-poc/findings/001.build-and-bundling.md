# Finding 001: Build and bundling

## Decision

Use Directus' Rollup build for the hook and one small tsdown build for the separate public
`./config` entry. Emit its declaration directly into the same `dist/` directory with `tsgo`.

```text
dist/index.js       Directus hook
dist/config.mjs     Bundled config helper and Zod runtime
dist/config.d.ts    Public TypeScript declaration
```

## Approaches considered

### Directus Rollup only

`extension.config.js` can customize the Rollup build used for the manifest entrypoint, but does not
provide a supported second entrypoint for `src/config.ts`. Re-exporting `defineConfig` from
`dist/index.js` would couple config consumers to the complete hook bundle and Directus SDK.

### Custom Rollup plugin

A plugin could start a second Rollup build, but would rely on undocumented Directus build behavior.
It would still need declaration generation plus watch-mode, cleanup, and error handling. The code
could be small, but the maintenance risk is high.

### Separate package

A separate config package would add a package and release surface for a small helper. This is
unnecessary for the POC.

### tsdown for the public entry

tsdown bundles Zod into `config.mjs`, while `tsgo` emits the small declaration beside it. This keeps
one `dist/` directory and one tsdown configuration without requiring consumers to mount `zod`.

## Rationale

The chosen approach keeps the Directus build conventional, gives the config helper an independent
public entry, avoids a standalone package, and avoids coupling consumers to the hook bundle or an
undocumented Rollup extension point.
